# v0.1.0 — provider-agnostic core

- **Date:** 2026-10-31
- **State:** merged into `main`
- **Scope:** first working slice of the orchestration sandbox: models, search, API.

## Goal

Talk to any LLM without the app caring which vendor it is, and keep every
offered provider usable on a **free** tier with no mock path.

## What went in

- `app/llm/` — `base.py` (provider protocol), `registry.py` (name → factory),
  `presets.py` (free-tier presets + console/key links), `openai_compat.py`
  (one implementation for every OpenAI-shaped endpoint), `model_picker.py`
  (`GET /models` based checks — never a chat call against a retired model id).
- Custom provider fully defined from `.env`: `LLM_PROVIDER=custom`,
  `CUSTOM_BASE_URL`, `CUSTOM_API_KEY`, `CUSTOM_MODEL`. No code change needed to
  add a vendor.
- `app/search/` — backends `ddg` and `wikipedia` need **no key and no server**;
  `tavily` / `serper` / `exa` / `google_cse` need a key only; `searxng` is opt-in
  and the only one that wants a running server.
- `app/agent.py` — one flow that can answer, search, or interleave both.
- Routes: `GET /health`, `POST /chat`, `POST /search`, `GET /providers`,
  `GET /providers/{name}/models`, `POST /diagnose`.

## Deliberate decisions

- **No mock provider.** If nothing is configured, the API returns
  `{"error":"configuration", ...}` with the exact env vars to set instead of a
  fabricated answer.
- Every provider entry carries its key console and its model list URL, so the UI
  can link straight to where a user gets a free key.

## Verify

```bash
python3 -m unittest discover -s tests -t .
curl -s localhost:8000/health | python3 -m json.tool
curl -s -X POST localhost:8000/chat -H 'content-type: application/json' \
     -d '{"prompt":"hi"}'
```

Without a key the last call must return HTTP 400 `configuration`, never a fake
reply.
