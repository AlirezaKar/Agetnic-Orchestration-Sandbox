# v0.13.0 — light theme, wider columns, drag-to-resize

- **Date:** 2026-11-03
- **State:** merged — see the index in [`README.md`](README.md) for the commit
- **Scope:** the page only — `app/static/index.html`,
  `app/static/assets/css/{extra,theme}.css`, `app/static/assets/js/app.js`,
  the UI tests and the docs. No API, orchestrator, config, provider or log
  change; the server contract is what 0.12.0 served.

## What this is

Three follow-ups to the studio redesign, all of them about *reading comfort*:
the page can now be read on a light background, the side columns got room to
breathe, and both side columns can be dragged to the width you want.

## 1. A light theme

`styles.css` is the supplied design system with the dark palette baked into
every component. Rather than fork or rewrite it, a new `theme.css` maps it:

```
1. tokens           --bg, --surface, --text, --accent … get light values
2. component remap   one override per rule that carried a literal colour
3. polish            page frame, code/JSON surfaces, transcript, panels,
                     banner, consent card, gradients, modal scrim
```

Every one of its 335 selectors is prefixed with `html[data-theme="light"]`, so
in dark mode the file is inert — a test asserts exactly that, because a single
unscoped rule would repaint the dark design from a stylesheet that loads last.

The switch is one icon button in the top bar (`#btn-theme`, sun ⇄ moon,
`aria-pressed`). The choice lives in `localStorage["agetnic.theme.v1"]` and an
inline script in `<head>` applies it **before the first paint**, so a light-mode
reload never flashes the dark palette. `meta[name=theme-color]` follows, and
`html[data-theme="light"] { color-scheme: light }` makes the native scrollbars
and form controls light too. Dark stays the default for a first visit: the
studio is designed as a dark room, light is the reading mode you opt into.

Contrast is checked, not eyeballed (there is no browser here): `--text` 16.1:1,
`--text-2` 8.3:1, `--muted` 5.2:1, `--accent` 5.3:1, `--mint` 4.9:1, `--amber`
5.2:1, `--red` 5.4:1 on `--surface`; the weakest tinted chip sits at 3.3:1,
above the 3:1 threshold for graphics. `--muted`, `--mint` and `--amber` were
tuned down from their first values for exactly that reason.

## 2. Wider, airier columns

| | 0.12.0 | 0.13.0 |
| --- | --- | --- |
| sidebar | 262 px (grid, fluid) | `--sidebar-width: 322px` fixed, drag 248–560 |
| inspector | 340 px | `--inspector-width: 412px` fixed, drag 300–680 |
| column edges | 0 | `--gutter-width: 7px` between every column |
| ≤1220 px | 245 / 310 | 288 / 372, bounded `minmax(250px, …)` / `minmax(320px, …)` |
| ≤980 px | 2 columns, inspector drawer | 276 / 360, inspector drawer, right handle hidden |
| ≤700 px | `display:block` | unchanged, both handles hidden |

Inside the wider columns the type scale and paddings were lifted as well: nav
rows 40 px with 13 px labels, session cards, provider rows, the health card,
run/history/agent rows, the trace rows, the run summary and the JSON view
(11 px) in the inspector.

## 3. Drag-to-resize

Two handles (`#gutter-left`, `#gutter-right`) sit between the columns — thin
lines that only show themselves on hover, with a `role="separator"` grip that
also answers the keyboard.

* drag → the new width is written as an inline custom property on `.workspace`;
  the stylesheet keeps owning the defaults, so the responsive breakpoints still
  work when nothing has been dragged;
* `localStorage["agetnic.layout.v1"]` → `{"sidebar": 322, "inspector": 412}`,
  applied at boot before the first paint of the columns;
* double-click a handle (or `Home`/`Enter` on it) → back to the design width;
* `←`/`→` nudge by 12 px, `Shift` makes it 48 px; `aria-valuenow` follows, so a
  screen reader announces the width;
* the middle column keeps `ROOM_FOR_CHAT` = 360 px: a drag stops there instead
  of squeezing the answer into a sliver, and below 980 px the inspector is an
  overlay that costs the grid no width at all;
* a column that is *already* wider than the budget keeps its width — the first
  drag shrinks it smoothly instead of snapping it somewhere else;
* the window `resize` event re-clamps both widths, so a layout saved on a wide
  monitor never strands the chat on a laptop.

New checks in `ui_smoke.js` (scenario G): the switch exists and starts dark;
clicking it sets `data-theme="light"`, `aria-pressed="true"`, the storage key
and `#f2f5fb` in the meta tag; clicking again returns to dark; a stored `light`
is applied on load *and* the button reflects it; `theme.css` is linked, every
one of its rules is scoped to the light root and it redefines the tokens; both
handles exist as separators; dragging writes `--sidebar-width` and the layout
key; the handle reports the width; the arrow keys nudge it; a double click
clears the inline width; the inspector handle resizes too; and a stored
`{sidebar, inspector}` is restored on load.

New checks in `test_api.py`: the light stylesheet is served and linked with
`?v=`, no selector in it is unscoped, it restates every core token plus
`color-scheme: light`, the page starts dark and carries the pre-paint script,
the choice is persisted, both handles are in the markup as separators, the
columns are driven by custom properties, and the drag/persistence markers are
in `app.js`.

**Honest limit:** there is still no browser in this sandbox, so the light theme
was verified by the cascade (jsdom), by a rule-by-rule coverage audit of
`styles.css`/`extra.css` (every dark rule that hardcodes a colour has a light
counterpart) and by the contrast numbers above — not by pixels. Open
<http://localhost:8000>, click the sun, and judge it by eye.
