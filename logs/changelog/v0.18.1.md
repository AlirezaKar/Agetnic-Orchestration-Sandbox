# v0.18.1 — a standalone access probe: tunnel, health, tokens, one verdict per service

- **Date:** 2026-10-31
- **Scope:** tooling — one new script (`scripts/aras_smoke.py`), docs; no app behaviour changes
- **State:** open — PR pending

## The problem

The v0.18.0 proxy fix did its job: the fake HTTP 503s disappeared and the
report changed to `ConnectError: All connection attempts failed` on all seven
services — the truth, which is that nothing is listening on the loopback
ports because the SSH tunnel is not open. But proving that from *outside* the
app was still awkward: the user's own probe script depends on `requests`
(which honours `HTTP_PROXY`, the exact trap v0.18.0 closed in-app, and whose
local install prints dependency-mismatch warnings), and it probes port 8106,
which the access rules forbid.

## What ships

**`scripts/aras_smoke.py`** — a single-file probe with three properties the
situation demands:

- **Standard library only, no project imports** (test-enforced): copy the one
  file next to any `.env` and run it anywhere Python exists — including
  Windows `cmd`. ASCII output only, so no console-codepage surprises.
- **Proxy-proof by construction**: an empty `urllib` `ProxyHandler` ignores
  `HTTP_PROXY`/`HTTPS_PROXY` entirely — loopback probes through a VPN proxy
  are precisely the failure it exists to expose.
- **Three layers per service, because each failure means a different fix**:
  1. TCP connect — closed port ⇒ "the tunnel is not forwarding this port";
  2. unauthenticated `/health` — non-200 with a body snippet ⇒ shows *who*
     actually answered (a proxy's error page is unmistakable);
  3. one **read-only** authenticated call with the token from `.env` —
     401/403 ⇒ token rejected; 400/422 on the deliberately empty probe body
     ⇒ the token *passed* the door, which is all the layer claims.

A final `DIAGNOSIS:` block aggregates: every port closed → open the tunnel;
everything answering but sick → a proxy is intercepting; rejected tokens are
listed by service. Tokens are never printed; port 8106 is never called
(test-enforced). Exit code 0 only when all seven services pass all layers.

**Docs:** the README's ARAS setup block gains the script and the Windows
one-line form of the tunnel command; the layout table lists the script.

## Tests

- `python3 -m pytest tests -q` → **603 passed** — 11 new in
  `tests/test_scripts.py`: `.env` parsing shapes, shared-token fallback, host
  derivation, the auth-verdict table (401 vs 400 vs 5xx), the aggregate
  diagnosis for all three field failures, a real-socket port check, **no
  `app` imports** and **no port 8106**, both asserted from the AST/source.
- pyflakes clean; verified end to end against a scripted fake proxy
  answering 503 on :8101 — the output names the port as open, quotes the
  proxy's body, and keeps "token not the problem" out of the way.

## Verify

```bash
python scripts/aras_smoke.py             # from the repo root, reads .env
python scripts/aras_smoke.py --json      # machine-readable
python aras_smoke.py --env C:\path\.env  # the copied-anywhere form (Windows)
```

## Honest limits

- The authenticated layer proves a token opens the door, not that every
  endpoint behind the door works — that is what the app's proof run is for.
- This sandbox has no tunnel, so the all-ports-closed and proxy-503 paths
  were exercised against local fakes; the first green run is the user's.
