# v0.10.0 — the orchestrator as a portable service beside the other services

- **Date:** 2026-11-01
- **State:** merged — PR #16, merge commit `db10169`
- **Scope:** `app/orchestrator/` only — new `service.py`, `contracts.py`, `host.py`
  and `README.md`; `manager.py`, `planner.py`, `executor.py`, `agents.py`,
  `trace.py`, `runlog.py`, `files.py` reorganised behind them. Host side:
  `app/main.py` (`/agents`, `/orchestrate`) and `scripts/doctor.py` now go
  through `OrchestratorService`. Logs, config, search, llm, memory and the UI
  are **unchanged**.

## Why

The orchestration logic is going to be reused in another project with a similar
architecture. It was already in its own folder, but the folder reached into the
application in five places, so it could not be lifted without edits:

| Coupling (before) | Where | Now |
|---|---|---|
| `from app.config import Settings, get_settings` | `manager.py`, `agents.py` | `contracts.OrchestratorSettings` (a protocol) |
| `from app.agent import WebSearchAgent` | `agents.py` | `contracts.AgentLoopFactory`, injected |
| `from app import logs` | `manager.py`, `executor.py`, `runlog.py` | `host.get_logger` / `host.log_dir` |

**Nothing about the algorithm changed.** Same classification, same planner
(rules → LLM briefs → dependency waves), same executor, same four agents, same
review, same synthesis, same trace events, same run-log records, same numbers.
This release only moves *what is wired to what*.

## What changed

### One entry point

```python
from app.orchestrator import OrchestrationRequest, OrchestratorService

service = OrchestratorService(
    settings,                        # any object shaped like OrchestratorSettings
    models=build_chain(settings),    # ModelChain
    search=build_search_chain(settings),   # SearchChain
    agent_loop=WebSearchAgent,       # AgentLoopFactory (optional)
    log_dir=None,                    # optional: where run records go
)
result = await service.run(OrchestrationRequest(message=…, attachments=[…]))
body   = service.payload(result)     # trace clipped for the browser
full   = service.payload(result, trace_limit=None)   # unclipped, like the run log
service.describe()                   # the payload GET /agents returns
service.boundary()                   # what is wired in on each port (for /health, docs)
```

`service.run()` is the old `Manager.run()` — the manager is now built by the
service (`service.manager()`), with the ports threaded through.

### Four declared ports

`contracts.py` has no imports from this repository, only protocols:

| Port | Shape |
|---|---|
| `ModelChain` | `await complete(messages, tools=None, temperature=…, max_tokens=…)` |
| `SearchChain` | `await search(query, limit)` |
| `AgentLoopFactory` | `factory(model_chain, search_chain, settings, observer=hook)` → `await run(...)` |
| `OrchestratorSettings` | 15 plain attributes (`orchestrator_*`, `llm_temperature`, `llm_max_tokens`, `agent_max_*`, `files_context_chars`) |

Plus `OrchestrationRequest(message, history, attachments, agents, planner,
synthesize, review)` and `from_payload(...)` to build it from an HTTP model.

### One host seam

`host.py` is the only file in the package that imports the app. Four functions:

| Hook | Default here | What another project supplies |
|---|---|---|
| `get_logger()` | `app.logs.get_logger` | its logger factory |
| `log_dir()` | `app.logs.log_dir` | where run records may go |
| `agent_loop()` | `app.agent.WebSearchAgent` | its single-agent tool loop |
| `default_settings()` | `app.config.get_settings` | its settings factory |

The logging itself — files, rotation, redaction, `agetnic.*` names — was not
touched. The orchestrator still writes the same lines to the same files, and
still writes the same `logs/orchestrator/runs.jsonl` + `<run-id>.json` records.

### The boundary is enforced by a test

`tests/test_orchestrator_service.py` parses the AST of every file in
`app/orchestrator/` and fails if:

- anything imports `app.llm`, `app.search`, `app.agent`, `app.memory`, `app.main`
  or `app.config` — those are siblings, reached through ports;
- any file other than `host.py` imports the host at all;
- `contracts.py` imports anything but the standard library;
- anything hides an import behind `importlib` / `__import__`.

The same file runs the **whole pipeline against foreign objects** — a settings
dataclass that is not `app.config.Settings`, a model chain with one method, a
search chain with one method, an injected agent loop — and asserts the run still
produces a plan, waves, a trace, a synthesis and an injectable run log.

### `app/orchestrator/README.md`

The service contract, the wiring sample, and the five-step porting checklist.

## What did not change

- **Logs** — `app/logs.py`, its handlers, rotation, redaction, `scripts.logs`.
- **The UI** — same HTML/JS/CSS; `GET /agents` and `POST /orchestrate` return the
  same JSON shape (the service's `describe()` and `payload()` produce it).
- **Config** — same `ORCHESTRATOR_*` variables and defaults.
- **Memory and attachments** — same stores, same paths, same behaviour.
- **Algorithms** — planner rules, LLM briefs, dependency scheduling, review,
  synthesis, deterministic merge, trace events: byte-for-byte the same code.

## Verify

```bash
python3 -m unittest discover -s tests -t .          # 418 tests
python3 -m unittest tests.test_orchestrator_service -v   # the boundary, on its own
python3 -m scripts.doctor --orchestrate             # still runs the manager through the service
node tests/ui_smoke.js http://localhost:8000        # the page is untouched
```

Expected after the refactor, with no other change: the same plan, the same
waves, the same trace event count and the same `run_id`/`log_path` behaviour as
v0.9.0.

## Known limits

- `files.py` still ships **inside** the service: the document agent's attachments
  are part of its input, so they travel with it. A host that already has a file
  service can ignore it and pass its own `Attachment` objects (only `.name`,
  `.text`, `.kind`, `.rows`, `.summary()` are read).
- Deep imports (`from app.orchestrator.manager import Manager`) still work and are
  used by the internal tests; the *host* now goes through `OrchestratorService`.
- The run log's directory comes from `host.log_dir()` unless a host injects
  `log_dir=`; the resolution order (argument → `LOG_DIR` → `logs/`) is unchanged.
