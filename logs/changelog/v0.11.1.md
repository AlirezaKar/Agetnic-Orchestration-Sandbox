# v0.11.1 — a tidier sidebar, and every panel scrolls instead of stretching the page

- **Date:** 2026-11-01
- **State:** merged — PR #20
- **Scope:** the page only — `app/static/index.html`,
  `app/static/assets/css/{styles,extra}.css`, `app/static/assets/js/app.js`.
  No API, orchestrator, config or log change.

## The two complaints

### 1. "The trace inspector is very long and makes the chat extend until its end"

The three columns were `height: calc(100vh - 65px)` with `min-height: auto` on
the grid children. A grid/flex child refuses to shrink below its content, so a
20 000-line trace record made the *inspector* taller than the row; the row was
pinned to the viewport but the item overflowed it, the document grew, and the
chat column ended where the JSON ended — far below the screen.

Fixed by framing the page instead of guessing the header height:

```css
body      { display: flex; flex-direction: column; overflow: hidden; }
.layout   { flex: 1 1 auto; min-height: 0; overflow: hidden; }   /* was 100vh-65px */
.layout > *, .main, .chat, .sidebar, .inspector { min-height: 0; min-width: 0; }
.trace-json { flex: 1 1 auto; min-height: 0; overflow: auto; }
```

Now the page never scrolls: the header stays on top, and the three columns take
exactly the rest of the screen. The sidebar scrolls its own list of panels, the
chat scrolls its messages, and the JSON scrolls inside the inspector — so the
inspector ends where the sidebar ends, not where the run record ends.

### 2. "Clean out the sidebar, make it more organized"

| Before | Now |
|---|---|
| Mode · Orchestrator · Memory · Run log · **Diagnostics** · Search backends · Run history (7 panels) | Mode · Agents · Memory · Runs · Search (5 panels) |
| Diagnostics panel duplicated the top-bar button | **top bar only**: `Run diagnostics` + the `Diag:` badge; the readable rows render at the top of the inspector, above the JSON |
| "Run log" and "Run history" were two panels with two paragraphs of explanation | one **Runs** panel with a `Saved` / `This tab` switch, one compact meta line, no prose |
| Memory carried a paragraph about `memory/` | just the counts: `3 session(s) · 8 turn(s) · memory/` |

The long explanatory paragraphs are gone from both — the panels say what they
are in the header, and the tooltips (`title=`) keep the detail one hover away.
The Runs panel is the growing one, so its list scrolls inside the sidebar.

Everything keeps working: `Saved` lists `logs/orchestrator/` from `GET /runs`,
`This tab` lists the runs remembered in `localStorage`; clicking either opens the
full record in the inspector. `⟳` reloads, `⌫` clears this tab's history.

New checks in `test_api.py` (`FrontendContractTests`):

* no diagnostics panel / no explanatory paragraphs in `app/static/index.html`;
* `.layout` clips and no longer uses `calc(100vh …)`, `.layout > *`, `.main`,
  `.chat`, `.inspector`, `.trace-json` all carry `min-height: 0`,

What was actually checked: no browser runs in this sandbox, so the scroll
contract is asserted on the real elements through jsdom's cascade (scenario **E**
above) rather than measured. If a panel ever stretches the page again, one of
those `min-height: 0px` / `overflow` assertions fails, and the element named in
the failure is the one to look at.
