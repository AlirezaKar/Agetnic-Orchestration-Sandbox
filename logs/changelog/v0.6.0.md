# v0.6.0 — lean `.env`, provider auto/manual, explicit models, `scripts.start`

- **Date:** 2026-10-31
- **State:** merged — PR #8, merge commit `1b50f80`
- **Scope:** configuration UX + one entry point. No provider client, route or log
  format changed.

## Why

1. `.env.example` had grown into a manual: 208 lines, most of them prose, and the
   model lines defaulted to `auto`, so it was unclear which model actually runs.
2. Choosing a provider meant editing `LLM_PROVIDER`, and a provider with a key
   but no model was silently "auto-discovered".
3. Running the project meant remembering four commands in the right order.
4. `artifacts/doctor.json` contained `"agent": null`, which reads like a failure.

## What changed

### `.env.example` is a config file again

- 208 → 96 lines, comments down to short section headers and one
  `# provider  key-link  models-link` line each.
- `LLM_MODEL`, `LLM_AUTO_SUBSTITUTE`, `LLM_MODEL_ATTEMPTS` are gone from the
  template (they still work; they are advanced knobs, documented in the README).
- Every `*_MODEL` line is **blank on purpose** — enforced by
  `tests/test_docs.py::test_models_are_never_prefilled`, together with a
  "comments must stay under 35%" rule so it cannot bloat again.

### Provider: auto or manual

```dotenv
LLM_PROVIDER=auto        # first provider with BOTH a key and a model wins
LLM_PROVIDER=gemini      # …or pin one, even if others are configured
```

Auto order: `groq → gemini → openrouter → mistral → cerebras → nvidia →
cloudflare → huggingface → ollama → lmstudio → custom`; `LLM_FALLBACKS` moves
named providers to the front. A key without a model never wins — the next
provider is tried.

### Model: always written by you

- The model comes from `<PROVIDER>_MODEL`, on the line under the key. A missing
  one is a reported gap (`status: "missing_model"`), not an invitation to guess.
- The id you write is the id that is called: `LLM_AUTO_SUBSTITUTE` now defaults
  to **false**. Retired-id clues are in `logs/error.log`, and
  `python -m scripts.check_providers --provider <name> --models` prints live ids.
- `LLM_MODEL` / `LLM_BASE_URL` / `LLM_API_KEY` remain manual-mode overrides; in
  auto mode they are ignored and `check_providers`/`doctor` say so out loud.
- Errors name the line to fill and where the ids are, e.g.
  `Missing env: GROQ_MODEL. Set GROQ_MODEL to a model id from
  https://console.groq.com/docs/models`.

### `python -m scripts.start`

| Flag | Effect |
| --- | --- |
| (none) | `check_providers` → `doctor` → `run.py` (uvicorn) |
| `--check-only` | stop after the checks; exit 1 if they fail |
| `--no-checks` | skip straight to the server |
| `--force` | serve even when a check failed |
| `--agent`, `-q "…"` | include the full agent round trip in the doctor step |
| `--port`, `--host`, `--reload`, `--log-level` | forwarded to `run.py` |

Checks run as child processes, so their tables and hints look exactly like the
standalone commands. Without a TTY it never blocks: failures mean exit 1 unless
`--force`.

### No more JSON nulls in the doctor

`artifacts/doctor.json` now records what was not run:
`{"skipped": true, "reason": "not requested; pass --agent …"}` for the agent,
the same shape for the model under `--search-only`. The terminal prints the same
sentence, so "agent: null" no longer looks like a failed check while it only
means "not asked for".

## Verify

```bash
python3 -m unittest discover -s tests -t .      # 193 tests
python -m scripts.start --check-only            # table, doctor, exit code
python -m scripts.start --force                 # also starts uvicorn
python -m scripts.check_providers               # core provider: auto -> …
```

Selection behaviour, checked without network:

```bash
GROQ_API_KEY=k GROQ_MODEL=openai/gpt-oss-120b python -m scripts.check_providers
# core provider: auto -> groq   (first ready wins)
GROQ_API_KEY=k python -m scripts.check_providers
# groq: set GROQ_MODEL  -> https://console.groq.com/docs/models
```

## Known limits

- Auto selection is static: it picks by configured key + model, not by measuring
  latency. Runtime failures still fall through the `LLM_FALLBACKS` chain.
- `--autofix` (writing a recommended id into `.env`) still exists, but it is
  opt-in: the default path is "you paste the id you want".
