# v0.15.0 — live thoughts (the run, shown while it happens)

- **Date:** 2026-11-04
- **State:** in review (this branch)
- **Scope:** the seam that lets a watcher see a run, and the chat surface that
  draws it. New `app/orchestrator/runbus.py` and `app/orchestrator/live.py`;
  `trace.py` (a sink), `manager.py` / `service.py` (pass it through), `main.py`
  (`POST /orchestrate/stream`), `app.js`, `extra.css`, `theme.css`, README and
  the tests. No change to the pipeline itself, the model clients, the search
  backends, the file store, memory or the log format.

## The problem

Auto mode took four seconds to four minutes, and for all of that the page said
one line — `thinking · planning agents…` — and then the answer simply appeared.
Everything the run was actually doing (the planner picking agents, each agent's
prompt, the tool it called, the evaluator's verdict, the manager deciding on a
second wave) was written to the trace *after* the fact and shown underneath the
answer, as `How this answer was built`. Watching someone think is the point of
an orchestration harness; hiding it is not.

Providers do not expose their hidden reasoning, but they do return the planning
text and every agent reply — that is what the trace already records. So the fix
is not "show the chain of thought": it is **relay the trace while it is written,
and let the reader group it.**

## Two new modules and one hook

```
app/orchestrator/runbus.py   RunBus / Channel — a run's events, relayed
app/orchestrator/live.py     a trace event → one "thought" for the page
app/orchestrator/trace.py    RunTrace(sink=…) — every add() is handed to the sink
```

`RunTrace.add()` calls `self.sink(event)` inside a `try/except`. A watcher that
throws (a socket that died, a broken queue) can never break a run — the trace is
still written, the run log is still produced, the answer still arrives.

`Channel.publish()` never awaits: it is a bounded `asyncio.Queue` (512) plus a
small ring history, with a `dropped` counter for a reader that falls behind. A
slow browser loses the *oldest* thoughts, never a wave, never the answer.
`RunBus` opens one channel per run (TTL 900 s, at most 64 kept), and `close()`
pushes `END` so the waiting generator wakes up immediately.

## The endpoint

`POST /orchestrate/stream` takes the same body as `POST /orchestrate` and runs
the *same* turn — same manager, same trace, same memory write — while relaying
its trace:

```
open     {"run_id": "run-20261104-064544-5573db"}
thought  {"seq": 7, "category": "agent", "group": "agent:search", "label": "Web researcher",
          "kind": "reply", "title": "Model reply (step 1)", "text": "…",
          "offset_ms": 4210, "at": "…", "detail": {"wave": 1, "model": "llama-3.3-70b"}}
result   {…the finished payload: identical to POST /orchestrate, including "session"}
error    {…the same failure body the JSON route returns}
```

| Field | Values |
| --- | --- |
| `group` | `planner` · `agent:<name>` · `evaluator` · `manager` (tools join their agent) |
| `kind` | `note` · `prompt` · `reply` · `tool` · `verdict` · `rewrite` · `status` |

Three rules in `live.py` keep it honest and cheap:

- **no system prompts, no hidden state** — a `prompt` thought carries the *last
  user message* (the task the agent was actually given), never the instructions
  around it;
- **no double reveal** — the synthesis reply *is* the answer, so it travels as a
  `status` (`Wrote the answer (812 chars)`) and the answer arrives once, in its
  own bubble;
- **bounded** — strings are clipped in the projection (700 chars; errors 240,
  because a TLS blob is not a thought). The unclipped record stays in
  `logs/orchestrator/`.

`detail` is a whitelist (`task`, `reason`, `status`, `latency_ms`, `wave`,
`round`, `quality`, `revised`, `tool`, `query`, `model`, `provider`, `agents`,
`items`, `gaps`, `tools`) — `messages` never crosses the socket.

Validation is unchanged: an unknown file, pending consent or a disabled
orchestrator still answer plain JSON with their status code and nothing is
streamed. `POST /orchestrate` and every script that used it keep working.

If the client disappears mid-run the run is **not** cancelled: the work is
already paid for, so the generator detaches it — the run finishes, is stored in
memory and in `logs/orchestrator/`, and the channel is closed and forgotten so
the rest of its events become no-ops. (A `done` callback logs the outcome, so a
late failure can never vanish.)

## On screen

Instead of the placeholder line, the assistant message now opens with a
**thoughts panel** above where the answer will be:

* **one group per actor** — Planner, each agent by its label, Evaluator,
  Manager — with a dot in the actor's colour, a count, and a spinner on whoever
  is working *right now*;
* **one row per thought**, folding open to the real text: the prompt the agent
  got, the tool it called (`web_search · latest python release`), what the model
  replied, the evaluator's verdict with a `4/5` line per report and the gaps it
  named, the manager's waves and its final "wrote the answer";
* the header carries a live clock and the latest action (`Web researcher ·
  Model reply (step 1)`), so a long run never looks stuck;
* the working group is open, finished ones fold away with their count still
  visible — unless you opened them yourself, in which case the page leaves them
  alone;
* when the run ends the panel says `Thought through 12 steps`, keeps every group
  one click away, and the answer lands in its own bubble underneath.

Both palettes cover it (the light theme needed the three `--*-soft` tints the
dark theme had and it did not), and `prefers-reduced-motion` swaps the spinner
and the fade-ins for a still frame.

## Verify

```
python3 -m unittest discover -s tests -t .        → 516 tests OK
python3 -m pyflakes app tests                     → clean
node tests/ui_smoke.js http://localhost:8000      → all checks passed
node tests/ui_consent.js http://localhost:8000    → all checks passed
```

New checks:

* **the bus** (`tests/test_live.py`) — order, `close()` → `END`, a publish after
  close, a slow reader losing the oldest events and counting the drops, a
  timeout instead of a hang, a bounded history, `forget`, `prune` keeping a live
  channel, dropping an expired one and capping the count;
* **the sink** — every event reaches it, and a sink that throws leaves the run
  and the trace untouched;
* **the projection** — planner/agent/tool/evaluator/manager grouping and labels,
  each agent its own group, the prompt thought carrying the last user message
  and *not* the system prompt, the synthesis reply becoming a status with no
  answer text, a verdict with scores and gaps, a rewrite with before/after, a
  failed tool named once and clipped, clipping at the limit, the detail
  whitelist dropping `messages`/keys, and a whole trace arriving in pipeline
  order;
* **the endpoint** (`OrchestrateStreamTests`) — the `open` frame first, the
  thoughts in planner → agent → evaluator → manager order with every field the
  page needs, the agent group carrying note/prompt/reply and its label, the
  final frame byte-identical in shape to `/orchestrate` (`answer`, `mode`,
  `run_id`, `orchestration`, `session`), a streamed run remembered like any
  other turn, validation errors still plain JSON (404, 503), a failing model
  still ending in a `result`, a reader that closes the stream mid-run leaving
  the run to finish and the turn remembered, and the bus cleaned up afterwards;
* **the UI** (jsdom) — a stubbed SSE body delivered in three reads with one
  frame split down the middle: the panel appears inside the assistant message
  with the bubble still empty, the spinner is on the working group, the groups
  are one per actor, the finished panel counts its steps and folds its groups
  while keeping the counts, the answer appears once in the bubble (and the
  synthesis row only says it wrote it), a group opens to the model's own words,
  the tool row names the query, the evaluator shows a score per report plus the
  gaps, and the light theme plus the reduced-motion rules are in the sheets.
  Scenario F now also covers the no-`ReadableStream` path (the same frames read
  in one go).

**Honest limits:** there is no browser in this sandbox — the UI is verified in
jsdom (structure, state, CSS contract), not painted. The model half of the
thoughts was exercised with fake chains; the sandbox has no provider key, so the
live run used here degraded to rules and its thoughts said exactly that
(`Planner model failed — keeping the rule-written briefs`), which is also a
useful thing to see on screen.
