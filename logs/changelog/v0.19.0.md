# v0.19.0 — ARAS only: the orchestrator, the UI and the ARAS microservices

- **Date:** 2026-11-10
- **Scope:** breaking — backend, settings, HTTP API, page, scripts, tests, docs
- **State:** open — pull request from branch `arena/c0593891-agetnic-orchestration-sandbox`

## The request

Keep three things and remove the rest: the **orchestrator**
(`app/orchestrator/`), the **UI** (`app/static/`) and the **ARAS
microservices** (`app/aras.py`). Every other model provider and every other
search backend goes — code, settings, scripts, routes, tests, docs, page copy.

Until now ARAS was one option among many: it *led* a chain of twelve model
providers and eight search backends and everything behind it stayed as a
fallback. That made "which model answered?" a question with twelve answers.
From this version there is one model (the ARAS router, :8101) and one search
(the ARAS web service, :8108), and nothing answers in their place.

## What was removed

| What | Where | Size |
|---|---|---|
| The model providers: presets, the OpenAI-compatible client, the registry and failover chain, the model picker | `app/llm/` (5 modules) | 1 284 lines |
| The search backends (DuckDuckGo, Wikipedia, Tavily, Serper, Exa, Google CSE, SearXNG), the search chain and the page reader | `app/search/` (5 modules) | 1 051 lines |
| The launcher and the provider checkers | `scripts/start.py`, `doctor.py`, `check_providers.py`, `check_search.py` | 885 lines |
| Their tests | `tests/test_llm.py`, `test_model_picker.py`, `test_search.py`, `test_selection.py` | 1 198 lines, 100 tests |
| 56 settings | `app/config.py`: 111 fields → 55 | — |
| 50 template variables | `.env.example`: 99 → 49 (163 lines → 91) | — |

Also gone, because they only existed for the removed parts:

- the agent's **`fetch_url` tool** — it read pages through a public reader
  service or a plain HTTP GET, both outside ARAS; ARAS web only *searches*, and
  no ARAS route for fetching a page is known. The agent loop now has exactly
  one tool, `web_search`;
- **`ARAS_MODEL=auto`** — it used the model picker. `auto` now counts as "not
  set" and is reported as missing;
- the routes **`GET /providers/{name}/models`** and **`GET /search/diagnose`**
  (both 404 now);
- the `provider` field of `POST /search` (ignored if sent) and the backend
  picker in the page's Search mode.

Nothing in `app/` imports `httpx` any more except `app/aras.py`: it is the one
place this app opens a network connection (test-enforced).

## What ships

**`app/config.py`** — ARAS-only settings: the `ARAS_*` block, two model-call
knobs (`LLM_TEMPERATURE`, `LLM_MAX_TOKENS`), the agent loop, the orchestrator,
memory and files. `aras_missing(service)` answers "which variables does this
service still need for the job it has here" — so the router also wants
`ARAS_MODEL`, retrieval and ingestion want `ARAS_COLLECTION`, data wants
tenant, owner and a source id. Variables from an older `.env` are ignored, not
an error.

**`app/aras.py`** — the one backend module. It now owns what used to live in
the removed packages: the reply types the ports hand back, the two adapters
that fill the orchestrator's model and search ports (`ArasModel`, `ArasSearch`),
a service catalogue for the page (`catalogue`), and one error type. Every
failure is an `ArasError` whose message starts with `[aras:<service>]` and
carries the HTTP status and a hint; "not configured" is its own subclass with
the list of missing variables. Timeouts, redirects, 401, 403, 429, a refused
model id and a refused tool call each get their own words, because each has a
different fix.

**`app/agent.py`** — the single-agent loop on ARAS types, with one tool.

**`app/main.py`** — the routes, reduced to one path per request:

| Route | Change |
|---|---|
| `GET /health` | new blocks `model{provider, service, endpoint, model, ready, missing}`, `search{…}` and `aras{configured, rag_ready, data_ready}`; `model_chain` / `search_chain` are `["aras"]` or `[]`; `skipped` is gone |
| `GET /config` | starts with `model_provider`, `model`, `model_ready`, `search_provider`, `search_ready` |
| `GET /providers` | now the seven ARAS services: `{service, label, port, role, route, endpoint, state, ready, configured, required, env[], missing_env[]}`; `state` is `ready`, `incomplete`, `off` or `not configured` |
| `GET /aras` | adds `model`, `model_ready`, `search_ready` and `missing{service: [env]}`; `router_in_model_chain` and `web_in_search_chain` are gone (there is no chain) |
| `GET /aras/models` | **new** — the model ids the router lists; needs only the router URL and token |
| `GET /diagnose` | one model ping, one search ping, every health probe; `hints` ordered from the most fundamental problem down |
| `POST /chat`, `POST /search` | errors are `400 configuration` (missing variables) or `502 aras` (the service failed); the old `502 provider` and `502 search` kinds are gone |
| `POST /orchestrate` | as before, a service that fails inside an agent is that agent's `failed` outcome in a `200`; the reason now names the ARAS service and carries its hint, and a search agent whose every search failed is `failed` too (it used to be `ok` — see "Found by running it"). An ARAS failure outside any agent uses the same two kinds |

`API_ROUTES` (what `GET /api`, the 404 body and `run.py` print) now lists every
route the app serves, including `DELETE /files/{id}` and the four `/audit`
routes it used to leave out — test-enforced in both directions.

**The orchestrator** — planning, waves, evaluator, review and synthesis are
untouched. Text changed where it named a removed part (docstrings, the skip
reason of the live audit checks, the package README), and two things changed
in how a failing service is reported (next paragraph). It still imports none
of its neighbours; `app/main.py` hands it the ARAS adapters as ports.

**Found by running it** — the app was started against a local stand-in for the
seven services (see Honest limits) and driven over real sockets: start-up,
every route, the page, and each kind of failure a service can answer with.
Four things did not hold up and were fixed:

- **`scripts/aras_smoke.py` failed a correct minimal setup.** It printed a
  `FAIL` row for every service without a token and exited 1 — under a summary
  line that said "All good". Only the router is required, so that made a
  router-and-web `.env` look broken. A service with no token is now `SKIP`:
  port and health are still shown, and it decides nothing. Exit code 0 means
  at least one service has a token and every one that has passes; the summary
  never says "All good" above a `FAIL`; `--json` carries `configured` and
  `verdict` per service.
- **The search agent reported `ok` after every search had failed.** With a
  rejected web token the model was told the search failed, wrote an answer
  from memory, and the run showed a green research agent with no sources.
  There is no second search service to fall back to, so this is a failed
  agent now: `status: failed`, the service's message and hint, an empty
  answer, and the manager writes from the reports that are left. A failed
  call followed by one that works stays `ok` and the report's detail counts
  the failure; an empty result list, or an answer the model gave without
  searching, stays `ok`. `POST /chat` is unchanged — it has one voice, so the
  model says the search failed and the reply lists the failure under `errors`.
- **A failed model call lost its hint.** A model call that raises inside an
  agent already failed that agent with the service's message; the executor
  now also passes on the exception's `hint` (for a rejected router token:
  which variable to check).
- **The proof line of the ARAS wiring panel named no model** — it read
  "answered by the ARAS router ()". The proof run asks for no synthesis, so
  the run itself names no model; the line now takes it from the agent that
  answered.

**The page** — same ids, same structure, same style rules (two comments in
`extra.css` were renamed); it is fed by the new payloads:

- status pills read `MODEL  <model id>`, `SEARCH  ARAS web`, `ARAS  n/m up` —
  or `not configured`, with the variables to set in the tooltip;
- the sidebar's "Search backends" list is **ARAS services**: one row per
  service, filled when ready, with the variables it still needs when not;
- Tools ▾ "Providers" is **ARAS services — what runs this app**: the model, web
  search, documents & data, with each service's role, endpoint and state;
- the ARAS wiring panel shows which service fills which job, and the proof run
  names the model the router answered with;
- Search mode has no backend picker; an error names the service that failed
  once, instead of repeating the same sentence as message and detail;
- the third sample task was "Compare providers" (search for free model APIs);
  it is now "Combine agents" — one request that sends the data agent and the
  search agent off in the same wave.

**`run.py`** is the launcher (`python run.py`; `python -m scripts.start` is
gone); its banner names the model, the search and every ARAS variable still
missing, and the server starts either way.

**Docs** — `README.md` rewritten around the three parts (1 078 → 1 031 lines);
`.env.example` is the ARAS block first, then the knobs; `logs/README.md`
loses its provider wording.

## Migration

1. **`.env`** — delete the old lines; nothing reads them: `LLM_PROVIDER`,
   `LLM_FALLBACKS`, `LLM_MODEL`, `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_TIMEOUT`,
   `LLM_AUTO_SUBSTITUTE`, `LLM_MODEL_ATTEMPTS`, every `GROQ_*`, `GEMINI_*`,
   `OPENROUTER_*`, `MISTRAL_*`, `CEREBRAS_*`, `NVIDIA_*`, `HUGGINGFACE_*`,
   `CLOUDFLARE_*`, `OLLAMA_*`, `LMSTUDIO_*` and `CUSTOM_*`, every `SEARCH_*`,
   `DUCKDUCKGO_*`, `WIKIPEDIA_LANG`, `TAVILY_API_KEY`, `SERPER_API_KEY`,
   `EXA_API_KEY`, `GOOGLE_CSE_*`, `SEARXNG_*`, `JINA_API_KEY`,
   `FETCH_MAX_CHARS`. Leaving them in is harmless.
2. **`ARAS_MODEL`** — write a real id. `auto` no longer works;
   `GET /aras/models` lists what the router serves.
3. **Starting** — `python run.py` (was `python -m scripts.start`).
   **Checking** — `python scripts/aras_smoke.py` and `GET /diagnose`
   (were `scripts.doctor`, `scripts.check_providers`, `scripts.check_search`).
4. **Clients of the API** — read `detail.service` and `detail.missing` instead
   of a provider name; expect `502 aras`; stop sending `provider` to
   `POST /search`; use `GET /aras/models` for model ids. In a
   `POST /orchestrate` reply, expect the search agent as `failed` (with
   `error` and `hint`) when no search came back — it used to be `ok`.
5. **`scripts/aras_smoke.py` in a script or a CI job** — a service without a
   token no longer fails the run (`SKIP`); the exit code is about the services
   that have one. `--json` rows carry `configured` and `verdict`.

## Honest limits

- **No live ARAS call was made from this sandbox** — it has no tunnel to the
  services. Every wire shape is tested against the shapes already recorded in
  the code and in `scripts/aras_smoke.py`; the first real run is the user's,
  and `GET /diagnose` is where to look first.
- **The end-to-end run used a stand-in, not ARAS**: seven loopback listeners
  on the service ports that check the token, the route and the body of each
  request and answer with scripted text. It shows this app's side of the wire
  — which service, route, token and body each job sends, and what the app
  does with each kind of failure. It cannot show that the real services
  accept those requests: the stand-in and the clients were written from the
  same reading of the API, so a wrong reading passes on both sides. The
  stand-in was a throwaway and is not in the repository.
- **With nothing configured there is no model at all.** That is the point of
  the release, but it means a fresh checkout answers nothing until the router
  block is filled. `POST /orchestrate` still returns a run (the agents report
  why they could not answer); `POST /chat` returns `400`.
- **Reading a page is gone** with `fetch_url`. If ARAS has a fetch or crawl
  route, wiring it in is one more client in `app/aras.py` and one more tool in
  `app/agent.py`.
- **PDFs keep their local parse**: OCR (:8102) is asked first when
  configured, then `pypdf` if it is installed — a library on this machine, not
  another service. When OCR fails and `pypdf` is absent, the `415` names
  `pypdf` and not the OCR failure; `python scripts/aras_smoke.py` shows a
  closed port or a rejected OCR token (`GET /aras` only probes health, which
  needs no token).
- Found on the way, older than this change and **left as they were**: the four
  `LOG_*` values are read from the process environment and not from `.env`
  (now said so in the template and both READMEs); a token that exists only
  in `.env` is redacted from logs by shape (`Bearer …`, `token=…`), not by
  value; `RELOAD` in `.env` is read by `python -m app.main` only (`run.py`
  takes `--reload`); when the model call fails inside the data or the
  document agent, what the agent had already worked out locally — the
  figures, the extract — is lost with it (with no model configured it is
  returned); and the audit's `live.latency` check runs its search agent on
  the audit's scripted loop, so its figure covers the router's evaluator and
  synthesis calls and no web search.
