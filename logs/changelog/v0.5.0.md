# v0.5.0 — real program logs in `logs/`

- **Date:** 2026-10-31
- **State:** merged — PR #6, merge commit `9547b54`
- **Scope:** logging only. No route, provider or search behaviour changed.

## Why

The previous release added `log/v<version>.md` — release notes in markdown. The
request was for **program logs**: what the terminal printed, what failed and
where, with process data. Release notes are not logs.

## What went in

`app/logs.py` — one module that owns every log file:

| File | Contents |
| --- | --- |
| `logs/agetnic.log` | everything at `LOG_LEVEL` and above, `pid` + logger on every line |
| `logs/error.log` | `WARNING`/`ERROR`/`CRITICAL` only, **with full tracebacks** |
| `logs/requests.log` | one line per HTTP call: method, path, status, ms, request id, client, bytes |
| `logs/terminal.log` | mirror of stdout/stderr — exactly what the terminal window showed |
| `logs/process.log` | one JSON line per start: pid, ppid, cwd, argv, python, platform, git commit, port, preflight problems |
| `logs/crash.log` | `faulthandler` output (segfault, hard abort, stack dump) |
| `logs/archive/` | rotated files (`agetnic.log.1`, `terminal-20261031-141702.log`, …) |

Behaviour:

- **Rotation** — 5 MB × 5 backups by default (`LOG_ROTATE_MB`, `LOG_BACKUPS`);
  `terminal.log` is rotated at startup past 10 MB, keeping the last 5.
- **Redaction** — env values from `*_API_KEY`, `*_TOKEN`, `*_SECRET`,
  `*_PASSWORD` plus `sk-…`, `gsk_…`, `AIza…`, `Bearer …`, `api_key=…` shapes are
  replaced with `«redacted»` before anything is written. Tracebacks included.
- **Never fatal** — an unwritable `LOG_DIR` degrades to console logging; a log
  failure cannot take down a request.
- **Crash capture** — `sys.excepthook`, `threading.excepthook` and an
  `Exception` handler on the API; a 500 now answers JSON with a `request_id`
  instead of an empty body, and the traceback goes to `error.log`.
- **uvicorn** — started with `log_config=None`, so uvicorn's own loggers propagate
  into these files instead of polluting stderr only. It also writes to
  `terminal.log` because `run.py` tees the terminal *before* logging starts.

`scripts/logs.py` — reading them without remembering paths:

```bash
python -m scripts.logs list          # files, sizes, last write
python -m scripts.logs tail -f       # follow agetnic.log
python -m scripts.logs tail error -n 100
python -m scripts.logs errors        # records with tracebacks
python -m scripts.logs requests --status 5xx --slowest 5
python -m scripts.logs process       # every start: pid, port, cwd, git
```

Other changes:

- `app/version.py` — the version now lives in exactly one place and is
  re-exported by `app.main`; `GET /version` also reports `logs` and `changelog`.
- `run.py` gained `--log-dir`, `--log-level`, `--no-terminal-log`; the banner
  prints where the logs are and how to tail them.
- `python -m uvicorn app.main:app` also logs now (lifespan startup).
- `scripts/doctor.py` runs are captured the same way.
- `log/` became `logs/`; release notes moved to `logs/changelog/` and the
  runtime files are git-ignored.

## Verify

```bash
python3 -m unittest discover -s tests -t .     # 40+ logging tests among the rest
python3 run.py --port 8000

python3 -m scripts.logs list
python3 -m scripts.logs requests
python3 -m scripts.logs process
curl -s localhost:8000/health > /dev/null
python3 -m scripts.logs tail requests -n 5      # the call you just made
curl -s localhost:8000/nope > /dev/null
python3 -m scripts.logs tail error -n 3         # the 404, as a WARNING
```

Force an error with a bad key to see a traceback land in `error.log`:

```bash
LLM_PROVIDER=groq GROQ_API_KEY=sk-broken python3 -m scripts.doctor
python3 -m scripts.logs errors
```

## Known limits

- With `--reload`, the reloader's worker writes app logs to the files normally,
  but its own stdout is inherited from the parent process, so a few worker-level
  print lines can bypass `terminal.log`. Run without `--reload` when you need a
  byte-exact terminal transcript.
- `logs/` is per machine; nothing is shipped or uploaded.
