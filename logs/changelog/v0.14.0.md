## What this is

The pipeline used to hand whatever the agents produced straight to the manager:

```
plan → agents (waves) → ────────────────────────► manager review → answer
```

The manager was reading raw, uneven reports. It could ask for another wave, but
it had no shared yardstick — one report rambles for 40 lines, another is two
sentences, a third "worked" but forgot the figure it computed. **Now there is a
gate between them:**

```
plan → agents (waves) → EVALUATOR → manager review → (new wave → EVALUATOR) → answer
```

One small completion does three things per run:

1. **scores** every report against the user's request — verdict
   (`keep` / `revise` / `fail`), a score out of 5, and the concrete issues;
2. **rewrites** the weak ones: drop the chatter, lead with the answer, keep the
   evidence, keep every URL and figure character for character;
3. **summarises** the set — one sentence plus the gaps the team did not close.

The manager then reads the *optimized* reports plus the evaluator's notes, and
only then decides whether another wave is worth the money. A follow-up wave comes
back through the same gate before it is read, and `ORCHESTRATOR_REVIEW_ROUNDS`
lets that loop run more than once.

## Three guarantees

| Guarantee | How |
| --- | --- |
| **Nothing is invented** | the prompt forbids new facts, and `keep_facts()` enforces the other half: a rewrite that loses a URL the original had (or is empty) is thrown away and the original is used, with `"the proposed rewrite dropped evidence — kept the original"` recorded as an issue |
| **Nothing is lost** | `agents[i].answer` keeps exactly what the agent wrote; `agents[i].optimized` holds the rewrite; the trace shows both (`before` / `after`) and the run log keeps the whole thing |
| **No model, no problem** | without a model chain — or when the call fails — the same stage runs a rule check: empty report, report under 80 characters, a `search` answer with no URL when sources were asked for, a `data` answer that lost its computed figures, an answer that ends mid-thought. It still scores, still names gaps, and cannot rewrite |

A report from an agent that failed or was skipped is listed with `usable: false`
and does not drag the run's quality score down.

## What the manager gets

`_results_block()` now hands it the rewritten text, marked and with the
evaluator's complaints attached:

```
### Web researcher (search) — ok, 812 ms · evaluated 4/5, revise, rewritten by the evaluator
Python 3.14 is the latest release (https://python.org/downloads).

evaluator issues: buries the answer in preamble; no publication date

Evaluator's summary: the web report is wordy and misses the date
Gaps the team did not close:
- the publication date
- Web researcher (search): revise, 4/5 — buries the answer in preamble
```

The synthesis prompt gets the same block plus one extra rule: *"if the
evaluator flagged a gap, say so in one sentence instead of filling it in."*

## Knobs

| Key | Default | What it does |
| --- | --- | --- |
| `ORCHESTRATOR_EVALUATE` | `true` | the gate itself |
| `ORCHESTRATOR_OPTIMIZE` | `true` | accept the rewrites; `false` = score and flag only |
| `ORCHESTRATOR_REVIEW_ROUNDS` | `1` | how many times the manager may ask for another wave |

`POST /orchestrate` takes a per-request `"evaluate": false` too. `GET /agents`
and `GET /health` now report `evaluate`, `optimize` and `review_rounds`.

## On screen

The run is still auditable end to end, and the new stage is visible in three
places:

* **the orchestration panel** — a head chip (`evaluator 4.3/5 · 2 revised`), an
  `Evaluator ·` note with the summary and the gaps, the rewritten reports named,
  a verdict on every agent chip (`4/5`, `revised 4/5`, amber for `revise`, red
  for `fail`), and its own trace row with a card per report;
* **the inspector** — a fourth run-summary metric (`4.0 (1✎) · evaluator /5`)
  and an **Evaluation** section listing every verdict, issue and gap;
* **the answer's meta line** — `evaluator 4.3/5 · 2 revised` next to the agent
  and call counts.

Dark and light themes both cover the new chips (`orch-chip.warn/.bad`,
`.agent-chip .verdict`), token-driven so the light palette needed only three
extra rules.

New checks:

* **rules** — a good report is `keep 5/5`; an empty one `fail`; a thin one is
  flagged; a sourceless `search` answer is flagged only when sources were asked
  for; a `data` answer without a digit is flagged; `keep_facts` refuses a rewrite
  that drops a URL or is empty;
* **parse** — unknown agents dropped, scores clamped, verdicts normalised, noise
  survives (`""`, `"not json"`, `[1,2,3]`, `{"reports": "nope"}`);
* **the stage** — the model's rewrite becomes `outcome.optimized` and the
  manager's text, while `outcome.answer` stays untouched; a rewrite that drops a
  source is refused and recorded; with no model the rules still score; a broken
  evaluator falls back to rules and says so in the trace; `optimize=False`
  scores without rewriting;
* **the pipeline** — the evaluator runs *after* the agents and *before* the
  synthesis (checked on the recorded prompts), the synthesis prompt carries the
  rewritten text, the issues and the gaps, the review prompt carries
  `Evaluator's summary` and the `rewritten by the evaluator` marker, a follow-up
  wave is evaluated as round 2, `review_rounds=2` allows exactly two reviews,
  `evaluate=False` skips the stage with a reason, the payload has the
  `evaluation` block, and the deterministic merge uses the optimized text;
* **the API** — `/agents` and `/health` describe the gate, `/orchestrate`
  returns `evaluation` with the stage ordered between `agent` and `synthesis`,
  and `{"evaluate": false}` turns it off;
* **the UI** (jsdom) — the head chip, the note with summary/gaps/rewritten
  names, the per-agent verdict and `revised` marker, the evaluator's own trace
  row with a card per report, and the inspector's metric plus Evaluation section.

**Honest limit:** the model half was exercised against fake chains, not a live
provider — the sandbox has no key, so the real-world prompt quality of the
rewrite is only as good as the prompt text. The rules half is fully covered.
