# v0.2.0 — the PR #1 frontend, restored

- **Date:** 2026-10-31T13:07:09Z
- **State:** merged — PR #3, merge commit `82a159e`
- **Scope:** UI only; the backend stayed as it was in 0.1.0.

## Why

The working UI from PR #1 was the thing users actually wanted back; the
rebuilt-in-a-hurry page was missing it. Constraint from the user: **restore the
frontend, keep the diagnostics**.

## What went in

- `app/static/index.html` — the PR #1 layout: composer, mode buttons, provider
  modal, search-backend list, history, inspector.
- `app/static/assets/css/styles.css`, `assets/css/extra.css` — restored the
  layout (grid) so the mode buttons sit in their row instead of stacking inline.
- `app/static/assets/js/app.js` — the PR #1 interactions plus the diagnostic
  panel kept intact.
- Nothing from PR #1's backend and none of its `/api/*` routes were restored;
  the UI was adapted to the routes that actually exist (`/chat`, `/search`,
  `/diagnose`, `/providers`).

## Decisions

- History and the inspector persist in `localStorage` (`agetnic.runs.v1`,
  `agetnic.mode.v1`) instead of server-side storage.
- Diagnostics stay one click away (`Diag` badge + panel) because that is what
  makes a broken provider obvious instead of silently degrading.

## Verify

```bash
python3 run.py --port 8000
# browser: http://localhost:8000/ — three mode buttons, provider modal, Diag button
curl -s -o /dev/null -w '%{http_code}\n' localhost:8000/assets/css/styles.css   # 200
```

## Known limits (found later, fixed in 0.4.0)

- The page hardcoded `/assets/...`, so it lost its CSS/JS whenever it was served
  under a prefix or opened as a copied file — dead buttons, unstyled panels.
- The UI addressed `/api/...` while the app served `/...` — `POST /api/chat`
  answered `{"detail":"Not Found"}`.
