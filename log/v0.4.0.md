# v0.4.0 — `Not Found` fixed; the page survives any mount point

- **Date:** 2026-10-31
- **State:** current
- **Scope:** routing, asset loading, launcher, per-version logging.

## Report

> The doctor says every model passes, but the backend does not work: sending a
> prompt answers **Not Found**, the buttons do nothing, and the modes show up
> alongside the rest of the parts.

Both symptoms had one root cause each, and neither was a provider problem —
which is why the model checks passed while the app looked dead.

## Root causes

1. **`POST /api/chat` → `{"detail":"Not Found"}`.** The UI addressed `/api/*`;
   the app only served `/*`. FastAPI answered with its own 404 body, so the
   failure looked like a missing backend rather than a wrong path.
2. **Dead buttons and unstyled modes.** `index.html` hardcoded `/assets/...`.
   Served under a prefix, a proxy, or opened as a copied file, both the CSS and
   the JS 404'd — no layout, no handlers. The modes stacked inline "alongside
   everything else" because the grid stylesheet never arrived.

## Fixes

- `app/main.py`
  - one route table (`API_ROUTES`) mounted **twice**: at root and under `/api`.
    `/chat` and `/api/chat` now return the same contract.
  - `GET /api` and `/api/` list the API routes; `/ui` 307-redirects to `.`
    (relative, so it works behind a prefix).
  - `HEAD /` and `HEAD /health` answer explicitly with an empty body.
  - unknown paths return actionable JSON: `error`, `message`, `hint`, `routes`,
    `openapi` — a typo now tells you where the API lives.
  - `/favicon.ico` → 204 (was a 404 per page load).
  - the index is served with `Cache-Control: no-store, must-revalidate`, so a
    restart is visible without a hard reload.
  - version exposure: `VERSION = "0.4.0"` in `/health` and `/version`.
- `app/static/index.html`
  - every asset is **relative** and cache-busted: `assets/css/styles.css?v=0.4.0`.
  - `<meta name="agetnic-version" content="0.4.0">` for a one-glance staleness check.
  - inline-styled connection banner (`#conn-banner`) with the probe list and a
    **Retry** button; it is styled inline on purpose, so it is readable even when
    the stylesheet is exactly what failed.
- `app/static/assets/js/app.js`
  - `candidateBases()` → `negotiate()` probes `health`, `/health`, `api/health`,
    `/api/health` on load and remembers whichever answers.
  - `apiUrl()` joins base and path like a URL, so `/api/` + `/health` is
    `/api/health` (0.3.0 produced `/api//health`).
  - `errorText()` prints the requested path and the server's `hint`.
  - `showBanner()` / `hideBanner()` / `checkStyles()`; if the grid stylesheet did
    not apply, the banner says so instead of leaving a mystery layout.
  - the composer label ends with `· v0.4.0`.
- `run.py` (new) — one command that starts UI + API together, prints the URLs,
  the route list and preflight warnings (missing `.env`, missing assets), and
  appends a startup line to `log/runtime/v0.4.0.log`.
- `app/applog.py` (new) — per-version runtime log helpers; never raises, so a
  read-only checkout still runs.
- `tests/test_api.py` — route/prefix/HEAD/404/banner/contract coverage, plus
  `FrontendContractTests` that fail if the page and the API drift apart again.

## Verify

```bash
python3 -m unittest discover -s tests -t .      # 121 tests, OK
python3 run.py --port 8000

curl -s localhost:8000/api/health                       # {"status":"ok",...,"version":"0.4.0"}
curl -s -X POST localhost:8000/api/chat \
     -H 'content-type: application/json' -d '{"prompt":"hi"}'   # 400 configuration, not 404
curl -s -o /dev/null -w '%{http_code}\n' -I localhost:8000/      # 200, empty body
curl -s localhost:8000/nope | python3 -m json.tool               # hint + routes
```

In the browser: the composer shows `· v0.4.0`, the badges read `LLM: …` and
`Search: …`, the `Diag` button fills the panel, and a prompt produces either an
answer or an explicit configuration error — never `Not Found`.

Node-based UI smoke test (optional, needs `npm i jsdom`):

```bash
node tests/ui_smoke.js http://localhost:8000
```

It runs three scenarios — normal host, static host (must show the red banner
while keeping the modes rendered), and an `/api`-only proxy — and fails if the
base negotiation or the error hints regress.

## Known limits

- A prompt still needs a provider key; without one the answer is the explicit
  configuration error listing the env vars.
- Provider egress was not reachable from the sandbox that built this, so live
  completions are verified with stubs; `python3 -m unittest` covers the
  transport, not the vendor.
