# v0.3.0 — intermediate routing rework (never released)

- **Date:** 2026-10-31
- **State:** superseded — never shipped as its own version
- **Scope:** first attempt at making the API reachable on the paths the browser
  was already using.

## Why this file exists

The "one log file per version" rule means gaps are documented, not skipped.
0.3.0 existed only inside a working tree: the router was split so a single route
table could be mounted twice, and the page's probes were rewritten. It was
replaced by 0.4.0 within the same session once two more defects surfaced, so
there is no commit, tag or released artifact for it.

## What it contained

- `API_ROUTES` as an explicit list instead of an implicit decorator order.
- A `router` object that is included both at root and under `/api`.
- Frontend probes for `health` / `/health` / `/api/health` before any real call.

## Why it was dropped

Two defects only showed up under a real server, so versioning it would have
shipped a partly fixed release:

1. `HEAD /` returned **405** (Starlette does not derive HEAD from `@app.get`),
   and replying with a JSON body to HEAD made uvicorn raise
   `RuntimeError: Response content longer than Content-Length`.
2. The base URL and the path were concatenated as strings, so a negotiated base
   of `/api/` produced `/api//health`.

Both are fixed and covered by tests in [v0.4.0](v0.4.0.md).
